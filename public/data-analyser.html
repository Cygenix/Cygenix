Data Analyser
Drop a file in. It works out what the file is and says how sure it is and why, profiles every column, flags what will break on load, and emits a target schema for SQL Server, Azure SQL, PostgreSQL, MySQL or SQLite — or CSV, JSON, NDJSON, XML, YAML, Markdown.
Nothing leaves this page while you analyse. The file is read and profiled in your browser — no upload, no server, no API key — so it is safe to try with real data, and it works with the connection down. If you hand the file on to Object Mapping, the column profile — names and inferred types, never the rows — is saved to your account as a job.
Make this a source. Saves the column profile — names and inferred types, never the rows — as a draft job in your account and opens it in Object Mapping, where you choose the target and map the columns.

What it flags, and what it will not do

  • AMBIGUOUS_DATE — dates like 01/02/2024 where day and month cannot be told apart from the data. Silently wrong for up to twelve days a month.
  • MIXED_TYPES — the share of values a strict target column will reject. INT_OVERFLOW — values past 32-bit, so the column must be BIGINT. CURRENCY_SYMBOLS — amounts carrying a sign that needs stripping.
  • Leading zeros stay string. 00417 and a postcode are not numbers, and a numeric cast destroys them.
  • Types, lengths and key candidates are inferred from the rows given — a starting point for review, not a claim about the full extract. The generated DDL says so in its header.
  • Parquet, Avro, SQLite and PDF are recognised from their first bytes and honestly refused: a browser cannot read them. Convert server-side.
  • Practical ceiling is roughly a 50 MB file. Above that, profile server-side.
